# LineGuide QA audit — 25 October 2026

## Scope
Reviewed the general-purpose v2.9 SOP/SWP application, embedded-photo import and preview, PDF export, local persistence, document revisions and safety input validation. No company document content or photographs are committed here.

## Fixed in this audit pull request
- **Silent photograph loss during imports:** the import normaliser previously discarded photo values that failed a simple data-URI check. It now rejects a malformed image before changing the library, with an explanatory warning.
- **Photograph visibility:** import confirmation and in-app preview show the number of embedded step photographs, so the user can verify whether the import contains images. The generated PDF remains uncluttered.
- **Unrecognised SWP risk-assessment method:** complete-field validation now rejects a value outside the two supported assessment routes.
- **Regression coverage:** new browser checks import two synthetic JPEG photos, verify they appear in the document and PDF, and confirm they survive revision; plus invalid-photo and SWP-method rejection.

## Evidence and limits
- The privately prepared six-photo test file was inspected outside the repository. Its six JPEG attachments decode correctly. A browser regression using the previous released engine displayed all six in the document preview and embedded all six in a nine-page PDF. The general-purpose current preview uses the same inline-image rendering pattern.
- GitHub Actions tests run Chromium, not physical iOS Safari/Home Screen mode.
- Photo-signature validation detects invalid/mislabeled data but is not a substitute for full-image rendering validation on every supported device.

## Remaining risk register
1. **High — localStorage capacity and repeated embedded photographs.** Each retained revision duplicates complete base64 image data. A photograph-heavy procedure can exhaust device storage after repeated edits. Move photo blobs and revisions to IndexedDB, with storage health indicators and tested backup/restore, before production use.
2. **High — approved revision lifecycle.** Editing an approved procedure creates a draft and archives the previous approved content; there is no separate current-approved pointer available for operational readers while a revision awaits approval. Keep the last approved revision prominently available until its replacement is actually approved.
3. **High — unauthenticated approvals.** Typed role names are only a prototype record. An organisational release needs real identity, permissions and auditable approval events.
4. **Medium — document import collision.** Matching document IDs can be overwritten after a confirmation. In team deployment, enforce conflict-safe import and explicit restore behaviour.
5. **Medium — mobile acceptance.** Repeat real iPhone Safari and Home Screen tests for import, image display, scrolling, local data persistence, file sharing and opening multi-page PDFs. Automated Chromium does not verify iOS WebKit behaviour.

## Expected manual checks
- Save a backup before testing or updating.
- Import a prepared sample through Home; check the photo count, open the full document and locate photographs alongside numbered steps.
- Export a PDF, verify the photo count and document-control labels, then re-open and revise.
- Confirm malformed-photo imports produce a warning and leave existing procedures untouched.
